# 02 调用流程和技术取舍

CLI校验输入→模型选search_documents→分页观察ID/日期/范围→模型选read_document→原文与条款claim_id返回→模型补查或respond→服务端核对引用、检索覆盖和适用性→形成回答。

每次动作附短依据；Trace包含参数、实际观察、后续动作，不记录内部思考。模型适配器要求每轮一个工具调用，不合规响应零动作执行并反馈模型纠正；HTTP/传输失败明确返回incomplete_model_error。默认24步，包含被拒绝的模型轮次，结束前必须有足够证据。

search_documents(query,cursor)每页3条。主题同义词归一化后找到同主题全部有效文档，必须连续取完分页；不能跳到末页伪称检索完整。未读原文不能引用，窄查询不能证明没有冲突，respond会返回BROAD_SEARCH_REQUIRED、READ_ORIGINALS_REQUIRED等可观察反馈。

read_document只接受已发现的有效文档。工具从单独一行的有限语法中抽取事实、确切字符起止和原文；附加或否定语句不作为同义事实。文档日期只用于溯源，只有明确active=false才排除。不同数值未明确优先级时冲突；标准版和专业版缺范围时请求确认。

respond(status,claim_ids)是模型选择的结束动作；代码要求引用集合与已读全部适用条款一致，拒绝假ID、漏冲突或不支持的状态。最终文字使用原文模板渲染，避免让模型自由补写无法校验的事实。模型不承担开放式答案写作，本项目不声称实现语义蕴含验证。

检索选择原生词项/同义词，便于三小时核心实现、离线复现和解释失败；不引入框架或向量数据库。代价是覆盖面窄，复杂制度、例外条件、跨主题问题可能返回资料外；这类误拒也属于待改进而不是凭空回答的理由。单次工具调用可失败一次恢复或多次失败后停止。

HTTP工具调用适配器及本机密码窗口从题2复制并独立调整，不依赖题2目录。必要的provider reasoning_content只在内存回传，不写Trace；原调用ID和实际观察正确回传。接口参考[DeepSeek官方工具调用说明](https://api-docs.deepseek.com/guides/tool_calls/)。
